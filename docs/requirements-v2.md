# めくトーク 要件（第2弾：デザインとサブ機能）

2026-11-09 にまとめた内容です。原本は Claude Docs の「めくトーク 要件定義（第2弾：デザインとサブ機能）」。第1弾の要件は [requirements.md](requirements.md)。

第2弾の軸は2つです。答え合わせを「全員で同時に迎える瞬間」にすることと、めくる瞬間をもっと派手にすること。第1弾の決定（意外性と答え合わせ感、参加者は終了まで他人の投稿を見られない、ログインなし）はそのまま守ります。

## サブ機能

### A. せーの公開

1. 最後の1枚、決めた回数、ホストの終了のどれで終わっても、一覧はまだ配らない。参加者の画面は「ホストの合図で公開します」
2. ホストの画面に「せーので公開」ボタン
3. 押すとサーバーが5秒後の時刻を決め、全員のスマホがサーバーの時計で 3・2・1 と数えてから一覧をめくる
4. ホストが押し忘れても、終了から15分で自動で公開する

受け入れ条件

- 公開時刻まで、一覧はホストを含むどの応答にも入らない（ルームコードだけで見られる `/info` も）
- 2台のスマホで、めくり始めのずれが0.5秒以内
- ホスト画面を再読み込みしてもボタンが出る。二度押ししても公開時刻は変わらない

### B. 答え合わせラウンド（投稿者名を公開する設定のときだけ）

1. 一覧が公開されても、名前は「？」のまま
2. ホストは「誰が書いたか当てる」か「名前を全部見せる」を選ぶ
3. 当てる場合、ホスト画面に話題を1つずつ大きく出す（引いた順、次に引かれなかったもの）。「答え」で名前が出て、参加者のスマホにも次の更新で出る
4. 「残りを全部見せる」でいつでも終われる

受け入れ条件

- まだ答えを出していない話題の名前は、どの応答にも入らない
- 二度押ししても2つ進まない（`POST /answers` は `{ upTo }` で冪等）。再読み込みすると同じ話題から再開する

### C. レア演出

- レアかどうかは引くたびに抽選する。話題そのものには付けない（投稿者が選べると誰が書いたかのヒントになる）
- 確率10%。レアなしが9回続いたら10回目は必ずレア（全体で約15%）。1段階だけ、見た目だけ
- ルームではサーバーが抽選して記録する（再読み込みしてもレアのまま、一覧では★）。用意されたデッキは端末で抽選する
- 演出：持ち上げたカードが金色に光り、震えが約0.4秒長くなる。表は金の枠と「RARE」の印、金色の光の筋と紙吹雪。動きを減らす設定では金の枠だけ

### D. 結果を残す

- **この話題でデッキを作る**（ホストだけ、公開後）：デッキ作成画面が話題を入れた状態で開く。「作る」を押すまで保存しない。名前は引き継がない
- **一覧を送る**（全員）：共有メニュー（使えなければコピー）。番号つきの一覧とアプリのURLで、名前は入れない

### E. 自分の話題が出たら表示

参加者の待ち画面で、自分の話題が引かれたら印が付く。振動はしない。届くのは自分の話題についてだけ。

### F. 公式デッキを3つ追加

「初対面」「もしも」「恋バナ」を各30枚。合わせて6デッキ。

## デザイン

- 配色A：夜のカードテーブルのまま、差し色をロゴの紺とラベンダーに寄せる。キャンディピンクは廃止。トークンは `primary`（#b5b6ce）、`accent`（#a9acdb）、`lamp`（#f2c46d）
- テーマ「よる」（ラベンダーから紺）を追加し、ルームのカードと新しいデッキの初期色にする
- 引いたカード：一番長い文節が1行に収まるよう文字を縮める（言葉の途中で改行しない）
- 引く演出：震える間に裏面で光らせ、めくる瞬間にカードの後ろから光の筋と紙吹雪
- カードの表：上部にデッキ色の帯（番号とデッキ名）、話題の下にロゴの曲線
- 言葉づかい：見出し「めくって、話そう。」、「カードをめくる」など、ガチャの言い回しをめくるに揃える
- ホスト画面：QR画面の数字を下のバーへ、終了の確認も固定バーに。ルーム作成ボタンを画面下に固定
- 公開した一覧は小さなカードとして順にめくれる
- ルームがない画面と404：ルームコードの入力欄とデッキへの導線、裏向きのカード

## 技術面

| 項目 | 対応 |
| --- | --- |
| データ移行 | `schema_migrations` に適用済みを記録し、未適用のときだけ排他ロックを取って順に適用（`src/lib/db/migrations.ts`）。変更は足す方向だけ |
| レート制限 | 同じDBの `rate_limits` 表で数える。超えたら429。アクセス元は `X-Forwarded-For` のうちプロキシが書いた部分だけを信じる（`TRUSTED_PROXY_HOPS`）。IPの上限はゆるく、存在しないルームコードだけ厳しく（IPごとに10分で60回。6文字のコードは約9億通りあるので総当たりは現実的でない）。超えたIPには、存在しないコードも違うトークンも429で返し、コードの有無を見分けられないようにする |
| 管理画面の署名鍵 | `ADMIN_SESSION_SECRET` が未設定ならランダムな鍵をDBに作る。ログインは12時間 |
| 404 | デッキのページは読み込み中表示の前に存在を確かめる |
| ポーリング | ルームの更新番号（`rooms.version`）を送り、変化がなければ「変化なし」だけ返す |
| 引く操作 | 何枚目を引くつもりか（`expectedOrder`）を送り、すでに引いていれば同じカードを返す |
| 送信サイズ | 64KBで断る |
